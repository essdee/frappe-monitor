# Phase 5 — Dashboard Full Coverage

**Goal:** operator can navigate Server → Bench → Site in the dashboard, drill into a site, and see its response-time trend, recent error lines, and slow-query feed — all driven by the URL-synced timeline filter from Phase 4.

**Branch:** continue on `feat/phase-2-server-metrics` (single working branch).

**Phase milestone:** start binary + VM + Loki, populate one cycle of metrics, open `/sites` in a browser, sort by worst, click into a site, see live response-time graph + the most recent error log lines for that site.

---

## Deliverables (7 tasks)

| # | Task | Brief |
|---|---|---|
| 1 | **Backend bench list/detail** | `GET /api/v1/benches` returns `[{server,bench}]` derived from `count by (server,bench)(frappe_bench_apps_count)`. `GET /api/v1/benches/{server}/{bench}` returns latest values for that bench's metrics (frappe_version, apps_count, supervisor counts, redis queue depths). Both paths via the existing metrics-query helper. |
| 2 | **Backend site list/detail** | `GET /api/v1/sites` returns `[{server,bench,site}]` from `count by (server,bench,site)(frappe_site_is_healthy)`. `GET /api/v1/sites/{server}/{bench}/{site}` returns latest health/response_ms + a 1h-window p95 of `frappe_site_http_response_ms`. |
| 3 | **Frontend benches view** | `/benches` — grid of bench cards. Each card: status (red if any of its sites is unhealthy), bench label (server/bench), frappe version, redis queue depths sparkline, supervisor count, site count link. |
| 4 | **Frontend bench detail** | `/benches/:server/:bench` — header + 3 charts (queue depth lines, supervisor, info pill) + a sites table for that bench. |
| 5 | **Frontend sites view** | `/sites` — table sorted worst-first (unhealthy → slowest). Columns: server, bench, site, status, p95 last hour, last response_ms, link. |
| 6 | **Frontend site detail** | `/sites/:server/:bench/:site` — header with current values, response-time chart, error log feed (LogQL `{server=...,bench=...,site=...,log_type="error"}`), slow query feed (`log_type="slow_query"`). Both feeds via the Phase 4 logs proxy. |
| 7 | **Smoke + Phase 5 acceptance** | Existing smoke gains: write a bench + site sample to VM, hit `GET /api/v1/benches`, `GET /api/v1/sites`, assert non-empty. Push a sample log entry, hit `GET /api/v1/logs/query` through the binary, assert it round-trips. |

## Open notes

- **Bench/site discovery via VM** keeps Phase 5 free of new schema work. A bench/site that disappears from the collector will fall off the dashboard after VM's retention catches up — acceptable for v1; Phase 7 can add an explicit "stale entry" indicator.
- **Slow-query feed**: the LogQL filter is a substring match on the `log_type="slow_query"` stream. Phase 7 may add JSON-aware filtering when slow query lines start carrying structured fields.
- **Sidebar nav** in `App.vue` un-greys `Benches` and `Sites` links (currently `Phase 5` tooltips).
