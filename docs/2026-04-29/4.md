# Phase 3 — Bench + Site Metrics + Loki for Logs

**Goal:** Extend the Phase-2 pull pipeline from server-only to the full **Server → Bench → Site** hierarchy, and start writing logs + slow queries to Loki.

**Branch:** continue on `feat/phase-2-server-metrics` (single working branch per current workflow).

**Phase milestone:** after one pull cycle, PromQL `frappe_bench_redis_queue_depth{server="...",bench="..."}` and `frappe_site_response_time_ms{server="...",bench="...",site="..."}` return data; LogQL `{server="...",bench="...",log_type="error"}` returns the most recent log lines.

---

## Deliverables (10 tasks)

| # | Task | Brief |
|---|---|---|
| 1 | **Collector v2** | Bash script grows `###BENCH:<name>` and `###SITE:<bench>:<site>` sections. Bench: Frappe version, apps+commits, Redis queue depths (short/default/long/failed), Redis memory, supervisor process states. Site: HTTP health + response time via `/api/method/ping`, DB size from `information_schema`, active sessions, file storage size (every Nth pull), error count. Bumps `VERSION` to `2.0.0`. |
| 2 | **Parser extensions** | `BenchFromSections([]Section, benchName)` and `SiteFromSections([]Section, benchName, siteName)`. Tokenizer is unchanged (already supports colon-bearing names). New fixture files per shape. |
| 3 | **Metrics types** | `BenchMetrics`, `SiteMetrics`, plus `LineProtocol` methods. Labels per master plan §4: `frappe_bench_*{server,bench}` and `frappe_site_*{server,bench,site}`. |
| 4 | **Pipeline extension** | `PullOnce` parses META + SERVER + all BENCH + all SITE sections from a single SSH call, batches every line into one VM POST per cycle. Half-failed sections (parse error in one bench) become per-section errors logged but don't fail the whole cycle. Server status still updated based on overall reachability. |
| 5 | **Loki client** | `internal/logs/lokiclient.go` with `Push(ctx, streams)` posting JSON to `/loki/api/v1/push`. Same shape as `internal/metrics/vmclient.go` — connection-timeout client + body cap on errors. |
| 6 | **`log_cursors` schema** | New ent entity: `(server_id, log_path) → byte_offset, last_seen_at`. Storage methods `GetLogCursor`, `SetLogCursor`. Cascading delete from server. |
| 7 | **Log tailing** | New `internal/collector/logtail.go`. Per (server, bench) + per log-file: SSH `tail -c +<offset>` to read incremental bytes since last cursor; parse into Loki streams; advance cursor. Phase 3 v1 covers `web.error.log`, `worker.error.log`, `schedule.error.log` (per bench). |
| 8 | **Slow-query ingestion** | Same `logtail` machinery applied to MariaDB's slow query log path. Stream label `log_type="slow_query"`. |
| 9 | **Docker compose for Loki** | Add `loki` service to `deploy/docker-compose.dev.yml` with retention 30d, bound to `127.0.0.1:3100`. Add `make loki-up`/`-down`/`-logs` targets. Update default config example to include `logs.loki_url`. |
| 10 | **Smoke + acceptance** | Extend `scripts/smoke.sh`: round-trip a sample stream to Loki, assert it comes back via LogQL. Confirm bench/site metric names in VM (`frappe_bench_*`, `frappe_site_*`) — same `-influxSkipSingleField` regression guard pattern as Phase 2. |

## Non-goals (deferred to later phases)

- **Per-bench scheduler intervals** — still one global cron spec from `cfg.scheduler.default_interval_seconds`.
- **Hot reload of bench/site lists** — process restart still required for newly-added rows.
- **UI** — Phase 4.
- **Log retention beyond Loki's defaults** — Loki's own retention config covers it.
- **High-cardinality metrics** — keep request IDs, user IDs, etc. out of label sets per master plan §6.

---

## Open design notes (refine while coding)

- **Bench discovery**: collector script enumerates `/home/<user>/frappe-bench/sites/*` per existing Frappe convention. The list of benches per server is dynamic — Phase 3 reads it from the script output, doesn't persist a `benches` table yet (deferred).
- **Site discovery**: each bench's `sites/<site>/site_config.json` is parsed by the script for DB name and other minimal fields. No persistence — site list lives in the most recent collector output.
- **Cursor scope**: `log_cursors` keyed by `(server_id, log_path)`. The `log_path` includes the bench dir, so per-bench separation falls out naturally without a `bench_id` column.
