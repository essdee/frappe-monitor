# Phase 2 — Server Metrics End-to-End: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Get **CPU, memory, disk, load, network, and uptime** from a real bench server flowing into **VictoriaMetrics** on a schedule, queryable by **PromQL**. Bench-level and site-level metrics are deferred to Phase 3.

**Architecture (from master plan §5, §6):**

```
[bench server] ── ssh exec ──► [Pool.Run]
                                   │
                                   ▼
                          stdout: ###META + ###SERVER + ###END
                                   │
                                   ▼
                          [parser]  parses sections → ServerMetrics
                                   │
                                   ▼
                          [vmclient] influx line protocol → POST /write
                                   │
                                   ▼
                          VictoriaMetrics @ :8428
```

**Phase milestone (master plan §12):** running `make run` with a configured server, after one pull cycle, the PromQL query `frappe_server_cpu_percent{server="<name>"}` against `:8428` returns a non-empty series.

**Tech additions on top of Phase 1:**
- `robfig/cron/v3` — scheduled pulls.
- A small HTTP client for VictoriaMetrics (stdlib `net/http`, no third-party).
- No new test deps.

**Phase 1 surface that this plan builds on:**
- `internal/ssh` — `Pool` already runs commands and pools connections; reused as-is.
- `internal/storage` — adds `SetCollectorVersion` if we track deployed version; current decision is to **not** persist version (re-check per pull, redeploy on mismatch). No schema change in Phase 2.
- `internal/api` — adds one route: `POST /api/v1/servers/{id}/deploy-collector`.
- `internal/config` — adds `metrics:` section (VM URL, push timeout).
- `cmd/monitor/main.go` — adds VM client + scheduler boot.

**Branch:** `feat/phase-2-server-metrics`, branched from `develop` after Phase 1 PR merges. Each task is one commit. PR into `develop`; user merges manually.

- [ ] **Step 1: Write the collector script**

```bash
#!/usr/bin/env bash
# frappe-monitor-collect.sh
# Outputs Frappe-monitor-format metrics to stdout. Phase 2: server section only.
# Version is the first line after the shebang and is checked by the monitor server.

set -euo pipefail

VERSION="1.0.0"

emit_meta() {
  echo "###META"
  echo "version=$VERSION"
  echo "timestamp=$(date +%s)"
  echo "hostname=$(hostname)"
  echo
}

emit_server() {
  echo "###SERVER"

  # CPU — first line of /proc/stat: aggregate counters
  read -r _ user nice system idle iowait irq softirq steal _ < /proc/stat
  echo "cpu_user=$user"
  echo "cpu_nice=$nice"
  echo "cpu_system=$system"
  echo "cpu_idle=$idle"
  echo "cpu_iowait=$iowait"
  echo "cpu_irq=$irq"
  echo "cpu_softirq=$softirq"
  echo "cpu_steal=$steal"

  # Memory — selected lines from /proc/meminfo
  awk '/^MemTotal:/ {print "mem_total_kb=" $2}
       /^MemAvailable:/ {print "mem_available_kb=" $2}
       /^MemFree:/ {print "mem_free_kb=" $2}
       /^Buffers:/ {print "mem_buffers_kb=" $2}
       /^Cached:/ {print "mem_cached_kb=" $2}
       /^SwapTotal:/ {print "swap_total_kb=" $2}
       /^SwapFree:/ {print "swap_free_kb=" $2}' /proc/meminfo

  # Load
  read -r l1 l5 l15 _ < /proc/loadavg
  echo "load_1m=$l1"
  echo "load_5m=$l5"
  echo "load_15m=$l15"

  # Uptime (seconds, fractional)
  read -r up _ < /proc/uptime
  echo "uptime_seconds=$up"

  # Disk — one disk_<mount>=<used_pct>;<used_bytes>;<total_bytes> line per mount
  df -B1 --output=target,used,size -x tmpfs -x devtmpfs -x squashfs 2>/dev/null \
    | tail -n +2 \
    | while read -r mount used total; do
        [ -z "$mount" ] && continue
        # sanitize mount path for label use later (the parser handles real path)
        echo "disk_used_bytes{mount=\"$mount\"}=$used"
        echo "disk_total_bytes{mount=\"$mount\"}=$total"
      done

  # Network — RX/TX bytes per interface (skip lo)
  awk '/^[ \t]*[a-zA-Z0-9]+:/ {
        gsub(":", "", $1)
        if ($1 == "lo") next
        printf "net_rx_bytes{iface=\"%s\"}=%s\n", $1, $2
        printf "net_tx_bytes{iface=\"%s\"}=%s\n", $1, $10
       }' /proc/net/dev

  echo
}

emit_meta
emit_server
echo "###END"
```

**Note on output format.** Lines inside a section are key-value pairs. Multi-instance metrics (per-mount disk, per-interface network) use Influx-style label braces inline (`disk_used_bytes{mount="/"}=123`). The parser splits these so the VM client emits one influx line per labeled value.

**Contract:** `POST /api/v1/servers/{id}/deploy-collector` uploads the embedded `scripts.CollectorScript` to `/usr/local/bin/frappe-monitor-collect.sh` on the target via the SSH executor. Returns `{deployed: true, version: "1.0.0"}` on success.

**Method:** Pipe the script over SSH using `cat > /usr/local/bin/frappe-monitor-collect.sh && chmod +x ...`. Use `Pool.Run` with the script as stdin — but `Pool.Run` doesn't currently accept stdin. **Phase 2 extends it:** add `RunWithInput(ctx, tgt, cmd, stdin string) (string, error)` to the `Executor` interface.

- [ ] Extend `internal/ssh/executor.go` interface: `RunWithInput`. Implement on `Pool` (pipe stdin via `*ssh.Session.StdinPipe`). Implement on `FakeExecutor` (capture stdin alongside the canned response).
- [ ] Update FakeExecutor tests to assert stdin capture for one case.
- [ ] Add deploy-collector handler:

```go
func (h *serverHandlers) deployCollector(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.Atoi(chi.URLParam(r, "id"))
    if err != nil { writeErr(w, 400, "invalid id"); return }
    srv, err := h.store.GetServer(r.Context(), id)
    if errors.Is(err, storage.ErrNotFound) { writeErr(w, 404, "server not found"); return }
    if err != nil { writeErr(w, 500, err.Error()); return }

    cmd := `cat > /usr/local/bin/frappe-monitor-collect.sh && chmod +x /usr/local/bin/frappe-monitor-collect.sh`
    _, err = h.exec.RunWithInput(r.Context(), tgtFromServer(srv), cmd, scripts.CollectorScript)
    if err != nil {
        writeErr(w, 500, "deploy failed: "+err.Error())
        return
    }
    writeJSON(w, 200, map[string]any{"deployed": true, "version": scripts.CollectorVersion})
}
```

- [ ] Test: not-found returns 404.

## Notes for the executor

- **Don't add bench/site collection** — that is Phase 3. Resist the urge to extend the parser to handle `###BENCH:` even though it's tempting; the parser interface stays the same in Phase 3 (more sections, same shape).
- **Don't add a `scheduler:` UI** — Phase 4 starts the dashboard. Phase 2 wires scheduler invisibly.
- **Don't introduce a metrics buffer/queue** — push synchronously from the pipeline. The master plan defers buffering to a Phase-7 hardening item ("if VM is down, buffer to disk").
- **Reuse `ssh.ErrAuth/ErrDial/ErrTimeout` sentinels** in pipeline error handling so the error_kind story stays consistent across endpoints.
- **Embed the script** rather than reading from disk in `deployCollector` — the binary is the unit of distribution, the script is part of it.
- **No schema change in Phase 2.** Collector version is verified per-pull via `head -3` and re-deployed on mismatch (Phase 3 may revisit if multiple collector schemas need to coexist).
- **Per-server cron interval** is deferred. Phase 2 uses the global default; per-server overrides become a small storage + scheduler change in Phase 3.
- **VictoriaMetrics retention** is 30d in dev compose (Phase 2 plan), 90d in production per master plan §6 — they're different config files.
