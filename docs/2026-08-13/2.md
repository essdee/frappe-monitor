# Local Frappe v16 metrics integration result

Date: 2026-08-13  
Branch tested and repaired: `main`

## Outcome

The complete metrics path works against the local Frappe v16 development
bench:

```text
monitor → SSH localhost → deployed collector → Frappe bench and sites
        → Influx line protocol → VictoriaMetrics → API → Vue dashboard
```

The test used the real monitor binary, OpenSSH with strict host-key checking,
VictoriaMetrics v1.148.0, the live bench at
`/mnt/storage/dev/frappe-v16`, and a real browser. It did not replace SSH,
VictoriaMetrics, or the web client with test doubles.

## Defects exposed and fixed

1. A first system-inventory capture failure attempted to insert a null payload
   into a non-null SQLite field. The monitor could therefore fail while merely
   trying to persist the original SSH error. The store now writes a non-null
   empty payload for an initial error, preserves `last_error`, and retains the
   last good payload on later transient failures. A regression test covers the
   first-failure case.
2. A custom VictoriaMetrics process without `-influxSkipSingleField` stores
   these Influx single-field metrics with a `_value` suffix, while the monitor
   queries the unsuffixed names. The bundled Compose service already had the
   correct flag and the smoke test already checked it; the required external
   deployment contract is now explicit in the configuration and architecture
   guides.

## Scope note

Loki was not started for this metrics-focused run, so the site detail page
correctly showed its log panel as unavailable (HTTP 502 from the monitor's Loki
proxy). This did not affect SSH discovery, collection, metric ingestion,
queries, alerts' metric inputs, or the dashboard metric views. Telegram
delivery and live-log ingestion require their separate service credentials and
were not exercised in this run.
