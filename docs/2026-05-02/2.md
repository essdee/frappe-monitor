# In-place server edit + mobile follow-up

User feedback after the first sweep:

> Still, the mobile responsiveness is not good. And I need to edit the server
> configs even after the config is done, like IP address changing, bench
> benches editing kind of.

## What changed

### Edit existing servers from the dashboard

`web/src/components/EditServerForm.vue` (new) + an **Edit** button on
`ServerDetail.vue`. Opens an in-page form pre-populated with the current
server's values; PATCHes via the existing `/api/v1/servers/{id}` endpoint.

Editable fields:

- `hostname` (covers IP-address changes for re-provisioned VMs)
- `ssh_user`
- `ssh_port`
- `ssh_key_path` (key rotation)
- `bench_paths` (add a non-standard layout the auto-discover misses, or
  pin a fleet to a known set of paths)

`name` is read-only — it's the metric label, and renaming would orphan
every historical series for this host. The hint text in the form spells
that out so operators don't get surprised.

After save, the parent re-fetches the row and clears stale probe /
deploy banners (the SSH target may have changed; "SSH reachable" against
the old IP would mislead).

### Mobile follow-up — the spots that still pinched

1. **Long monospace strings overflowed the viewport.** Hostnames, paths,
   and key paths are all in `<code>`. Made `code { overflow-wrap:
   anywhere; word-break: break-word }` global so a single 60-char path
   can't push the layout wider than the phone.

2. **`min-width: 0` on shrink-targets.** Without it a flex/grid child
   (the main column under the sidebar, the chart canvas inside the
   summary grid, the long hostname inside `ServerCard.header`) claims
   intrinsic width and forces a horizontal scrollbar on the whole page.
   Applied at the .main, .charts, .grid, .summary, .firing-list,
   .proc-grid level + on `.name` / `.header` inside `ServerCard`.

3. **iOS Safari was zooming on form-control focus.** Inputs/selects/
   textareas under the ≤720px breakpoint now pin to `font-size: 16px`
   (the threshold below which Safari auto-zooms). The body font stays
   at 14px so the rest of the dashboard isn't suddenly gigantic.

4. **Sidebar at ≤480px was overflowing horizontally.** Brand row and
   nav row now wrap independently; nav itself horizontally scrolls
   inside its row (with hidden scrollbar) so 4 routes + Sign-out fit
   on a 360px-wide phone. Sign-out moves to the right via `margin-left:
   auto`.

5. **`ServerCard` errors used to truncate.** The dashboard surfaces
   collector errors via this card; on a phone the card is full-width
   so there's no reason to ellipsis. Errors now wrap to multiple lines
   on ≤720px.

6. **`ServerDetail` action row.** Test SSH / Deploy / Edit / Delete
   used to wrap into awkward two-column-with-stranded-Delete layouts.
   Now an explicit 2×2 grid: Test SSH + Deploy in row 1, Edit + Delete
   in row 2. Predictable, equal widths, Delete adjacent to Edit
   instead of sitting alone underneath.
