# Bug-fix sweep — logout, reachability, mobile, collector robustness

User-reported issues (operator dashboard on mobile):

1. Click Sign-out → bounces straight back into the dashboard.
2. Server detail shows "unreachable" with an error even though the host is
   actually reachable.
3. Mobile responsiveness is bad across the app.
4. Some metrics-collection paths surface unhelpful errors / stall on busy
   benches.

## What changed

### 1. Logout no longer bounces back to dashboard

`App.vue` now calls `confirm()` before signing out — the icon-only mobile nav
puts Sign-out next to the route links, and a misclick used to drop the
operator out of the dashboard mid-task. After confirming, the request fires
and even if it errors we still hard-navigate to `/login?signed_out=1`.

`Login.vue` now skips the `whoami()` auto-redirect when `?signed_out=1` is
present. The previous flow checked whoami on mount; if the cookie-clear
hadn't fully propagated yet (TLS-terminating proxy, in-flight request,
browser cache), whoami answered 200 and the user was bounced into the
dashboard, making logout look like a no-op.

### 2. "Unreachable when reachable" — three fixes

a. **Storage** (`internal/storage/ent_store.go`): `UpsertSystemSnapshot` now
   treats an empty `Payload` as "leave existing payload alone." Previously a
   transient SSH blip during refresh wiped the last good inventory and the
   System-details card went blank with a red "Last capture failed" banner.

b. **Pipeline** (`internal/collector/pipeline.go`): the `len(Disks)==0 ||
   len(Net)==0` check was too aggressive — minimal containers and overlay-
   only mounts tripped it even with CPU/memory perfectly populated, and the
   server got marked unreachable. Now requires BOTH empty (real torn output)
   to fail; either-empty just logs a warning and pushes whatever's available.

c. **ServerDetail.vue**: after a successful Test-SSH probe, the page now
   re-fetches the server row so the badge flips from "unreachable" to
   "reachable" without a manual page reload. Without this, the green probe-
   result banner sat right next to a red status badge — the exact contradiction
   the operator flagged.

### 3. Mobile responsiveness — comprehensive pass

All views: `Servers`, `Benches`, `Sites`, `ServerDetail`, `BenchDetail`,
`SiteDetail`, `Alerts`, `Login`, plus shared components `TimelineFilter`,
`MetricChart`, `AddServerForm`, `App.vue` sidebar.

Highlights:

- Sidebar nav on phones: tap targets are now ≥38px high; Sign-out gets a
  warning tint on hover (mobile users misclick it because it sits next to
  the routes); brand text wraps to its own row on ≤420px.
- `TimelineFilter`: presets become a horizontally-scrollable strip
  (1h/6h/24h/3d don't wrap into 3 lines anymore), refresh selector pinned
  right, the absolute window timestamps demote to a small footer.
- Page-headers stack title + actions vertically on phones; refresh + Add-
  server buttons go full-width in a single row.
- `Sites` table reformats to per-site cards on ≤720px (same `data-label`
  trick `Alerts` already used).
- `MetricChart` height drops from 240→200px on phones and now uses
  `ResizeObserver` so charts re-fit when grid layouts swap from 2-col to 1-
  col without a window-resize event.

### 4. Collector robustness

- `internal/collector/pipeline.go`: when the bash collector's ERR trap
  fires, the resulting `###ERROR` section's `exit_code` and `line` now
  surface in the wrapped error message ("collector script error (exit=N
  line=M)") instead of being swallowed and replaced with a generic
  downstream "missing META section."
- `scripts/frappe-monitor-collect.sh` (v2.5.0): added a wall-clock budget
  for the site-probe phase (`SITE_PROBE_BUDGET_S`, default 20s). Sites past
  the budget emit an `is_healthy=0 / http_status_code=0` shape via
  `emit_site … skip` — same emit shape, no curl call. This stops 30+-site
  benches from getting killed mid-loop by SSH's 30s command timeout, which
  used to drop the trailing `###END` and trigger a parse failure.
- The `is_healthy` test in `emit_site` now uses a `case` pattern to
  validate that `http_code` is purely numeric before comparing — prevents
  edge cases (empty string, "000") from triggering a `[: integer expression
  expected` error under `set -e`.

## Tests

New / updated:

- `pipeline_test.go::TestPullOnce_EmptyDisksAcceptedWhenNetPresent` (formerly
  `…_EmptyDisksRejected`) — soft-rejection rule.
- `pipeline_test.go::TestPullOnce_EmptyDisksAndNetRejected` — strict-rejection
  case.
- `pipeline_test.go::TestPullOnce_ScriptErrorSectionSurfacesExitCode` —
  exit_code + line propagate through the wrapped error.
- `ent_store_test.go::TestUpsertSystemSnapshot_ErrorOnlyPreservesPayload` —
  failure-only update keeps the prior good payload.

Full suite: `go test ./...` green; `npm run build` green.
