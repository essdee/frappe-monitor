# Phase 6 + Phase 7 (v1) — Finish the Project

**Goal:** ship a single-tenant production-ready binary. After this lands, frappe-monitor can run on the public internet with a password, lets the operator manage the fleet from the dashboard, and pages a Telegram chat when something breaks.

**Branch:** continue on `feat/phase-2-server-metrics` (single working branch).

---

## Phase 6 — Telegram alerting

| # | Deliverable |
|---|---|
| 1 | `internal/alerts` package: `Rule`, `Evaluator`, `TelegramClient` |
| 2 | New ent schema `AlertState` — per-(rule, fingerprint) status + last_notified_at |
| 3 | Alert evaluation loop on its own cron (default 60s) |
| 4 | Default rules baked in: `site_unhealthy`, `disk_almost_full`, `redis_queue_high`, `server_unreachable` |
| 5 | Recovery notifications when a firing series disappears from the rule's result |
| 6 | Config schema + admin-managed chat IDs + bot token |

**Single bot, fan-out to all chat IDs, send-only.** No two-way commands, no per-chat subscriptions, no acks. Documented decision (memory: "Telegram alerting decisions").

**Cooldown** prevents notification storms: same (rule, fingerprint) suppresses repeats for `notify_repeat_seconds` (default 1h).

## Phase 7 (v1 minimal) — operator-blocking gaps

| # | Deliverable |
|---|---|

| 8 | `DELETE /api/v1/servers/{id}` — remove a server (cascades log cursors) |

## Non-goals (deferred to a later phase / hardening backlog)

- **Deploy markers** — needs a `deploy_events` table and an annotation timeline; a post-v1 nicety.
- **Multi-tenant access scoping** — single password is enough for one team; multi-tenant is real Phase 7+.
- **Per-server schedule overrides** — global is fine for ≤25 servers.
- **Site-scoped log labels** — Frappe's per-bench logs already cover the failure modes operators care about.
- **Search UI** — Sites already has a substring filter; bench/server search is low priority.

These move to `docs/hardening-backlog.md` with rationale.

---

## Acceptance criteria

After this phase:

1. `sudo ./deploy/install.sh` on a fresh server, set `auth.password` + `alerts.telegram.*` in config, restart → dashboard prompts for credentials, alerts fire to the configured chat IDs.
2. Operator can add, rename, and remove servers entirely from the dashboard.
3. Existing smoke (`scripts/smoke.sh`) still passes; new Phase 6/7 sections cover auth + delete + alert-rule round-trip.
4. `docs/guide/*` reflects every operator-visible change.
