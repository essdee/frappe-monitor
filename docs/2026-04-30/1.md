## Non-trivial decisions

### `-search.latencyOffset=0s` in dev compose
VictoriaMetrics defaults to a 30-second instant-query lag (a buffer for late-arriving samples). In dev that made the dashboard look frozen for 30s after every collector push. The dev compose now sets the offset to zero so `/api/v1/query` reflects fresh writes immediately. Production compose may keep the default if late samples are common — this knob is dev-scoped.

### Logs are bench-scoped on Site detail
The Loki collector tags streams with `server`, `bench`, and `log_type`, but not `site` — Frappe's per-bench log files don't carry a site label today. Site detail's "recent error log lines" panel uses `{server=,bench=,log_type="error"}` and notes the limitation in-page. Phase 7 adds per-site log tailing for sites that have their own `sites/<site>/logs/<file>.log` files.

### Hierarchy endpoints are VM-derived, not stored
`listBenches` runs `count by (server, bench) (frappe_bench_apps_count)` against VM; same idea for sites. A bench/site that stops being scraped will fall off the dashboard after VM retention purges its last sample (~30d). Phase 7 can add an explicit "stale" indicator.
