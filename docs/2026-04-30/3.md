## Non-trivial decisions

### HTTP basic auth instead of cookie sessions
Browsers handle the credential prompt natively, so the SPA needs no login page, no logout button, no cookie middleware, no session store. Single shared password covers single-tenant deployments — the smallest surface that's actually safe. Multi-tenant access (per-user, role-based) lands in Phase 7 v2.

### Alerts service is opt-in, not opt-out
Default config has `alerts.enabled: false`. Operators must explicitly turn it on after wiring up a bot. This avoids a fresh install spamming a placeholder chat or failing on a missing token.

### Rules are static config, not editable from the dashboard
Per memory `project_telegram_alerting`: send-only, admin-managed. Rules in YAML keep them under git/audit. The dashboard never lets a casual user disable an alert without a config change being reviewed.

### Reconciliation in the evaluator (not in Telegram)
The `(rule, fingerprint) → last_notified_at` table lives in SQLite next to the server registry. This means: cooldown survives restarts, recovery notifications don't double-fire on bounce, fingerprints stay stable across processes (deterministic hash of sorted labels).

### Per-server CRUD in the SPA reuses existing endpoints
The Add Server form posts to the same endpoint operators have been curl'ing since Phase 1. PATCH + DELETE are new but follow the same DTO shapes. No new service layer; storage gets two methods.

None of these are v1 blockers — they're operator-visible polish that becomes worthwhile once you have ≥ 25 servers, multiple teams using the dashboard, or a deploy pipeline rich enough to feed events to.

## Operator checklist for first production deploy

1. `git clone … && sudo ./deploy/install.sh` — installs binary, creates systemd unit, brings up VM + Loki.
2. Generate + set `auth.password`. Restart.
3. Generate + set Telegram bot token, populate `alerts.telegram.chat_ids`. Set `alerts.enabled: true`. Restart.
4. Add Caddy in front for TLS (`deploy/Caddyfile.example`).
5. Add bench servers via the dashboard (Add server button).
6. Smoke-test by killing one bench's network — within 5 min you should get a `server_unreachable` Telegram message; bring it back and you get the recovery message.

That's the project finished.
